# Docs Module Rules

- Scope: project plans, migration notes, operational runbooks, deployment notes, and maintenance documentation.
- Documentation changes must not modify business logic or deployment behavior.
- Keep migration docs practical and phase-based, with verification and rollback notes.
- Do not include secrets, SMTP passwords, API keys, or private tokens in documentation.
- Prefer concise file maps, command examples, and current-state notes over speculative rewrites.
